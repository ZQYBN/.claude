# 注释规范

## 文件头注释（必须）

每个文件必须以多行注释开头，说明文件职责与范围。新建文件必须包含，修改已有文件时若原注释已与代码不一致，须同步更新。

**前端**（TypeScript / JavaScript）：

```tsx
/**
 * <一句话描述文件职责>
 *
 * @remarks
 * - <关键设计决策或约束>
 * - <与其他模块的关系>
 */
```

**后端**（Java）：

```java
/**
 * <一句话描述类职责>
 *
 * <p>上下文：<在哪个模块中、服务于哪个功能></p>
 */
```

## 函数与方法注释

- 公开 API、导出函数、Controller 方法、Service 方法：必须写注释
- 内部辅助函数与仅返回单一值的 getter 函数：可省略
- 仅返回 JSX 且不含业务逻辑的渲染函数：可省略
- 注释写"为什么"（Why），不写"做什么"（What）

## 禁止事项

- 不写 JSDoc 中无意义的 `@param` 与 `@returns`（例如 `@param id - the id`）
- 不在代码内写行注释解释"做什么"（例如 `// set loading to true`）
- 不写 TODO 注释（使用项目 `docs/todo/` 目录管理待办事项）
